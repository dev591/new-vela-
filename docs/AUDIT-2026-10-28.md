## 🔴 Critical

1. **Authentication without authorization.** `main.py:721` only checks that *a* token exists; ~5 of 141 routes check
   role or ownership.
   - A patient token can call `GET /api/patients/list` (every patient, every hospital), any `/api/patients/{id}`,
     `DELETE /api/upload/document/{id}`, lab report submit, discharge, `/api/mem0/wipe-patient`.
   - Managers can read other hospitals' data; any hospital manager can verify any solo doctor (`main.py:7977`).
   - `list_patients` (`main.py:1380`) falls back to all patients when the hospital filter errors (`except: pass`).
   - Fix: one `require(roles=..., same_hospital=True, own_patient=True)` dependency on every route. Tokens already
     carry `role`, `hospital_id`, `staff_id`.
2. **Database likely open to the internet.** The backend's main client uses the anon key (`main.py:832`);
   `supabase_fixes.sql:114` disables RLS "same access model as your existing tables"; the anon key ships to browsers
   (`VITE_SUPABASE_ANON_KEY`). Not verified against live Supabase — check RLS per table in the dashboard.
   Fix: backend uses only the service-role key; enable RLS on all tables with no anon policies.
3. **Socket.IO has no auth.** `connect` (`main.py:907`) accepts anyone; `join_hospital`/`join_room` join any room;
   79 of 83 `sio.emit` calls broadcast to all clients (registrations, emergency intakes, lab orders).
   Fix: verify token on connect, join only the session's hospital room, always emit to a room.
4. **Secrets in the frontend bundle.** `VITE_ELEVENLABS_API_KEY` (`AtlasCore.ts:475`) is inlined by Vite — move
   TTS behind the backend and rotate the key. Staff passwords hardcoded on login tiles (`Login.tsx:33-60`).
   Owner login hardcoded `dev@vela.ai` / `dev1`, plaintext compare (`main.py:8212`).
5. **Real patient sign-up / sign-in broken (only demo login works).**
   - `/api/patient/self-register` returns no token → `/api/appointments/book` 401s (`PatientPortal.tsx:235`).
     Breaks "booking without an account".
   - Sign-in (`PatientPortal.tsx:305-316`) ignores the Supabase password result, then calls auth-protected
     `/api/patient/by-email`; if that were public, knowing an email would be enough to sign in as that patient.
   - Fix: backend `/api/patient/login` that verifies the Supabase password and issues a token; self-register
     returns a token.

## 🟡 Code quality

- `main.py` is 8,648 lines — split into routers (auth, patients, lab, admissions, network, owner, atlas) like
  `receptionist.py`.
- Duplicates: `predict_disease` defined twice (`main.py:875`, `:8593`); two health endpoints; `add_staff_basic` vs
  `add_staff`.
- Split storage: lab orders + audit log in local `vela_local.db`, everything else in Supabase.
- Most routes take raw `data: dict` — use Pydantic models.
- Disease model: Kaggle symptom dataset, 42 test samples; 97.6% accuracy is not clinically meaningful — label as
  demo or remove.
- Frontend: very large page components; mixed `fetch`/`axios`; 268 lint warnings; 15 `console.log`; 10 pollers
  alongside sockets.
- Bundle: main chunk 527 KB, mapbox 1.7 MB — lazy-load landing hero (three/gsap) and Atlas.
- Repo hygiene: README is the Vite template; root clutter (`.vsix`, PDFs, `test.mp3`, empty `--noEmit/`, `tsc/`);
  no backend `.env.example`.
- Owner/manager endpoints (`onboard_hospital`, `add_staff`, owner stats) appear partly stubbed — verify before demoing.

## 🧩 Missing features

**Clinical / operational:** billing & invoices (GST, insurance claims, refunds) · signed printable e-prescriptions
with interaction gate · pharmacy & inventory · nurse role (vitals charting, med schedule) · consent capture.

**Patient side:** working patient login + phone OTP · SMS/WhatsApp notifications · multi-language UI (i18n) ·
installable PWA · teleconsultation.

**Platform / compliance:** FHIR R4 / HL7 · ABDM / ABHA ID · proper roles & permissions, tamper-evident audit,
break-glass, retention · pagination · backups & monitoring · automated tests & CI.

## Suggested order

1. Permission checks on every route + authenticated sockets.
2. Lock down the DB (service-role key only, RLS on).
3. ElevenLabs behind backend, remove hardcoded passwords, rotate exposed keys.
4. Fix patient login/booking tokens.
5. Audit-log role fix, login rate limits, upload limits.
6. Split `main.py`, add pytest suite for auth rules.
7. Features: billing, SMS, ABHA/FHIR, PWA, i18n.
